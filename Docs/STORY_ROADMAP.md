# ストーリーモード ロードマップ

> ストーリーモード全体の方針と、タウン（区切り）ごとの計画書の作り方をまとめる。
> 「（案）」は Claude の提案で、まだ確認していないもの。決まったら（案）を外す。
> 遊びのルール・数値が決まって実装したら、`PENGUIN_MONSTER_SPEC.md` にも反映する（仕様書が正）。

## 1. 目標

- 本家ポケモンに近い「町を歩いて、捕まえて、育てて、道場を巡る」ストーリーモードを作る
- 一気に最後まで作らず、**タウン（区切り）を1つずつ足していく**。1つ足すたびに遊べる状態にする
- 最終的な大きさ: 道場 8つ ＋ 四天王（本家と同じ）。区切りは約 9 個
- 区切りごとに新しいペンモンを **約30体**（進化を含む）足す。全部で約 250〜270 体

## 3. 全体の設計（共通の仕組み）

最初の区切り（タウン1）で一度だけ作り、後の区切りはデータを足すだけで済むようにする。

### 3.1 レベル

- 今の能力値の式（HP＝種族値＋75、ほか＝種族値＋20）は、本家の式（個体値31・努力値0）の Lv50 の場合と同じ
- → 本家の式をレベルで一般化し、Lv50 のときは今と同じ値になるようにする。ドラフト・勝ち抜き戦・オンラインは何も変わらない
  - HP ＝ ⌊(2×種族値＋31)×Lv÷100⌋ ＋ Lv ＋ 10
  - ほか ＝ ⌊(2×種族値＋31)×Lv÷100⌋ ＋ 5
- ダメージ式の `2×Lv÷5＋2` は攻撃する側のレベルで計算する（今は定数 `LevelFactor`）
- オンラインの「自分のチーム」は、レベルに関係なく Lv50 として戦う

### 3.2 個体（捕まえたペンモン1体）

定義表の `MonsterDefinition`（種）とは別に、捕まえた1体を表す純C#のクラスを作る（案: `OwnedMonster`）。

| 中身 | 内容 |
| --- | --- |
| 種 | No |
| ニックネーム | 当面はなし（種の名前）（案） |
| レベル・経験値 | 1〜100 |
| 技 | 覚えている技（最大4つ） |
| 今の HP・状態異常 | 戦いの後も持ち越す |
| 持ち物 | 1つ（ストーリーで拾う・もらう） |

- バトルに出すときは、今の持ち物の写し（`WithItem`）と同じ考え方で「技・持ち物・レベルを差し替えた写し」を作る。バトルの中身はなるべく変えない

### 3.3 データ（定義表）

区切りごとにファイルを足す。値は定義表が正（仕様書には書かない）。

| 定義表 | 中身 |
| --- | --- |
| `MonsterTable` | 今と同じ。No.151〜 を区切りごとの partial に足す |
| 覚える技の表 | 種ごとに「Lv N で 技」の列。最初から覚えている技も含める |
| 進化の表 | 種ごとに「Lv N で No.M へ」。当面はレベル進化だけ（道具・懐きの進化は必要になったら） |
| 種ごとの数値 | 捕まえやすさ・倒したときの経験値・経験値の伸び方（案: 本家の「中速」と「やや遅い」の2種類だけ） |
| マップ | 文字の表（1文字＝1マス）＋出入口・人・看板・草むらの出現表 |
| トレーナー | 名前・見た目・セリフ・手持ち（No・Lv・技は省略したら覚える技の表から自動）・賞金 |
| 出来事（イベント） | 会話・最初の3体をもらう・ライバル戦などの台本。進み具合はフラグで持つ |

### 3.4 フィールド

- マップの中身・移動・当たり判定・出来事の進行は純C#（`noEngineReferences`）に置き、EditMode でテストする
- 表示は View（Tilemap にコードで作ったタイルを置く。カメラは主人公を追う）
- 草むらを1歩進むたびに、マップの出現率で野生に出会う
- 出入口（扉・マップの端）で別のマップへ切り替える

### 3.5 ストーリーのバトル

今の `BattleEngine` を使う。足すものだけ書く。

- 形式: 手持ち全員 vs 相手全員（シングル）。野生は1体
- コマンド: 戦う / バッグ / ペンモン / 逃げる（逃げるは野生だけ）
- 経験値: 倒した相手から、場に出た子で分ける（案: 本家の第6世代以降の「全員に入る」ではなく、出た子だけ）
- レベルアップ・技を覚える（4つ埋まっていたら1つ忘れるか選ぶ）・進化はバトルの後に出す
- 全滅したら最後に回復した場所へ戻る。お金は半分になる（案）
- CPU の賢さは区切りが進むほど上げる（道場の主は つよい）

### 3.6 セーブ

- 1つだけ（スロットは1つ）。メニューの「記録する」で保存（案: 本家のレポート）
- 中身: 主人公の位置・手持ち・あずかり箱・バッグ・お金・フラグ・図鑑（見た / 捕まえた）・羽章
- 保存の形は純C#のデータを JSON にして PlayerPrefs に入れる（WebGL でも使える）
- 今のセーブ（最高連勝数・設定）とは別のキーにする

### 3.7 シーンとフォルダ（案）

- シーンは今の `PenguinMonsterScene` 1つのまま、フィールドの層を足す（バトル画面・`BattleController` をそのまま使い回せるため）。SceneBuilder に `.Field` 系の partial を足す
- フォルダ（案）

```text
Scripts/
├── Battle/               # 今のまま（レベル対応だけ足す）
├── Story/                # ストーリーのルール（純C#、PenguinMonster.Story.asmdef、noEngineReferences。Battle を参照）
│   ├── Data/             # 覚える技・進化・マップ・トレーナー・出来事の定義表（区切りごとに Town01*.cs …）
│   ├── Field/            # マップ・移動・当たり判定・出会い
│   ├── Party/            # 個体・手持ち・あずかり箱・経験値・進化
│   ├── Items/            # バッグ・お金・捕獲
│   └── Save/             # セーブデータ（純C#の形）
└── View/Story/           # フィールドの表示・十字キー・会話窓・メニュー
```

## 4. 区切りの追加の仕方

1つの区切りを足すとき、`Docs/PLAN_STORY_TOWNxx.md` を作る。中身の型:

1. この区切りで遊べるようになること（町・道路・道場・物語の出来事）
2. 新しいペンモン一覧（No・名前・タイプ・進化・題材）。約30体
3. 新しい技・特性・持ち物（あれば）
4. マップ一覧（大きさ・何があるか）
5. トレーナー・道場の主の手持ちとレベル
6. フェーズ分け（各フェーズの終わりで遊べる状態にする）
7. 仕様書のどこを直すか
