# ペンモン 仕様書

> 対話で中身を決めながら埋めていく。未定の項目は「未定」と書いておく。「（案）」は Claude の提案で、まだ確認していないもの。

## 1. 概要

ペンギンだけのモンスターをドラフトで集めて戦う、ターン制の対戦ゲーム。見た目と手触りはダイヤモンド・パール風の2D。ストーリーやフィールド探索はない。

| 項目 | 内容 |
| --- | --- |
| アプリ名 | ペンモン |
| ジャンル | ターン制モンスター対戦（3vs3 シングル。ダブルスは後で追加） |
| グラフィック | 2Dドット絵（ペンギンはコードで生成） |
| プレイ人数 | 1人（勝ち抜き戦・CPU戦）/ 2人（オンライン・参加コード） |
| 1試合の長さ | 5〜10分が目安 |
| ペンモンの数 | 最初 24 体 → 50 → 75 → 100 体と段階的に増やす |
| プラットフォーム | Android / Windows / ブラウザ（WebGL）。横画面固定 |

### 1.1 モード

| モード | 編成 | 相手 | ゴール |
| --- | --- | --- | --- |
| 勝ち抜き戦（1人） | 最初にドラフトで6体。最後まで同じチーム | CPU（勝つほど強くなる） | 何連勝できるか。7戦ごとにボス |
| オンライン対戦（2人） | 毎回ドラフトで6体 | 友達（参加コードで接続） | 相手の3体を全員たおす |

### 1.2 権利まわりの方針

ゲームの仕組み（タイプ相性・種族値・ダメージ式など）はポケモンを参考にするが、タイプ名・技名・特性名・持ち物名・見た目はすべてオリジナルにする。

## 2. ゲームの流れ

```text
タイトル
 ├ 勝ち抜き戦 → ドラフト → [見せ合い → 選出 → バトル → 結果] をくり返す（負けたら終わり）
 ├ オンライン対戦 → 部屋を作る / コードで参加 → ドラフト → 見せ合い → 選出 → バトル → 結果
 ├ ずかん
 ├ タイプ相性表
 ├ あそびかた
 └ 設定
```

### 2.1 ドラフト

- ランダムな3体から1体を選ぶ×6回で6体そろえる
- 提示はプレイヤーごとに別々。相手と同じペンギンを取ってもよい。自分がすでに取ったペンギンは出ない
- 候補は全ペンモンから純ランダム（タイプの偏りの補正はしない）
- オンラインは1回15秒。過ぎたら3体からランダム
- 提示数（3）・回数（6）・制限時間（15秒）はバランス定義クラスに置く

### 2.2 見せ合い・選出

- お互いの6体を見せ合い、バトルに出す3体と先頭を選ぶ
- オンラインは60秒。過ぎたら上から3体

### 2.3 勝ち抜き戦

- 最初のドラフトで決めた6体で、負けるまで戦い続ける（途中で入れ替えはしない）
- 毎試合の前に見せ合い・選出をする。HP・状態異常は毎試合全回復
- 7戦目・14戦目…はボス戦。ボスは固定の強いチームを持つ（ボスの人物・チームは未定）
- CPU の賢さは3段階で、連勝数に応じて上がる。チームも強いペンギンが出やすくなる（§4.8）
- 最高連勝数を記録する

### 2.4 勝敗

- 相手の場に出た3体を全員ひんしにしたら勝ち
- 相手が切断したら勝ち扱い（オンライン）

## 3. ペンモン

### 3.1 データの持ち方

- 純C#の定義表（コード）で持つ。値はこの仕様書には書かない（定義表と二重管理になるため）。ゲーム内の「ずかん」で確認できる
- 1体あたりの中身: No / 名前 / タイプ（1〜2個）/ 種族値6つ / 技4つ / 特性1つ / 持ち物1つ / 見た目（パーツの組み合わせ）

### 3.2 能力値

- 6種: HP / こうげき / ぼうぎょ / とくこう / とくぼう / すばやさ
- 育成はなし。全員 Lv50 固定。個体値・努力値・性格はなく、能力値は種族値だけで決まる
- 実数値の計算式（案。個体値31・努力値0 相当）
  - HP = `種族値 + 75`
  - それ以外 = `種族値 + 20`

### 3.3 タイプ（10種）

| タイプ | イメージ |
| --- | --- |
| ノーマル | ふつうのペンギン |
| こおり | 氷山・雪。主役のタイプで体数は多め |
| うみ | 水・波 |
| ひ | 火山・たき火 |
| かみなり | 嵐・電気 |
| こけ | 海藻・苔 |
| いわ | 岩場・大地 |
| とり | 空への憧れ・風 |
| やみ | 極夜・シャチなどの天敵 |
| オーロラ | 不思議・光 |

| うみ | | | ½ | 2 | | ½ | 2 | | | |

## 4. バトル

### 4.1 ターンの流れ

1. 両者が同時に行動（技4つ / 交代）を選ぶ
2. 交代が先、次に技の優先度が高い順、同じならすばやさが高い順（同速はランダム）
3. 順に行動する。ひんしになったペンモンは行動しない
4. ターン終わりの処理（どく・やけどのダメージなど）
5. ひんしになった側は次のペンモンを出す（控えがいなければ負け）

### 4.2 技

- 技は全ペンモンで共通の技表から選ぶ（定義表）。1体4つ固定
- 中身: 名前 / タイプ / 分類（物理・特殊・変化）/ 威力 / 命中 / 優先度 / 追加効果
- PP はない（3vs3 ならほぼ気にならないため）

### 4.3 ダメージ

ポケモンと同じ式を使う（Lv50）。

```text
ダメージ = ((22 × 威力 × 攻撃 ÷ 防御) ÷ 50 + 2)
          × 急所(1.5) × 乱数(0.85〜1.00) × タイプ一致(1.5) × 相性 × やけど(物理なら0.5)
```

- 計算は式の左から順に掛け、掛けるたびに小数を切り捨てる。相性が 0 でなければ最低 1 ダメージ
- 物理技は こうげき / ぼうぎょ、特殊技は とくこう / とくぼう を使う
- 急所は 1/24。急所のときは自分の下がった攻撃ランクと相手の上がった防御ランクを無視する
- 命中は「技の命中 × 命中ランク ÷ 回避ランク」（回避ランクを入れるかは未定）
- 乱数は `System.Random`（オンラインはホストの乱数だけを使う）

### 4.4 状態異常

| 状態 | 効果（原作に準拠） |
| --- | --- |
| まひ | すばやさ半分、1/4で動けない |
| どく | ターン終わりに最大HPの1/8 |
| もうどく | ターン終わりに 1/16, 2/16, 3/16…と増える |
| やけど | ターン終わりに 1/16、物理のダメージ半分 |
| ねむり | 1〜3ターン動けない |
| こおり | 1/5で解ける。ひタイプの技を受けると解ける |
| こんらん | 1/3で自分を攻撃（交代で治る） |

- 名前はオリジナルにするかは未定（「まひ」「どく」は一般名詞なのでそのままでもよい）

### 4.5 能力変化（ランク）

- こうげき〜すばやさ・命中・回避が -6〜+6
- 倍率は原作どおり（2/8 〜 8/2、命中・回避は 3/9 〜 9/3）
- 交代すると元に戻る

### 4.6 特性・持ち物（後のフェーズ）

- 特性はペンモンごとに1つ固定
- 持ち物もペンモンごとに1つ固定（ドラフトのカードに表示する）
- 種類・中身は未定

### 4.7 オンラインの制限時間

- 1ターン30秒。過ぎたら一番上の技を自動で使う

### 4.8 CPU

| 賢さ | 行動 |
| --- | --- |
| よわい | 技をランダムに選ぶ |
| ふつう | 一番ダメージが出る技を選ぶ |
| つよい | ふつう ＋ 不利なら交代する |

- 連勝数ごとの賢さ・チームの強さの切り替えは未定（例: 1〜6戦目は よわい→ふつう、ボス以降は つよい）

## 5. 成長・収集

- 育成・収集はない。記録は勝ち抜き戦の最高連勝数だけ

## 6. 画面・ビジュアル

- 横画面固定（Android / Windows / ブラウザ）
- バトル画面はダイヤモンド・パール風: 手前左に自分（後ろ姿）、奥右に相手（正面）。HPバーと名前の枠、下にメッセージ窓とコマンド
- ペンモンの絵はコードで生成するドット絵。1体につき正面と後ろの2枚（サイズは 64x64 案）
- 絵は基本ペンギン＋パーツの組み合わせで作る（パーツの種類は未定）

## 7. UI・演出・サウンド

- メッセージは「こうかは ばつぐんだ！」のような一文ずつの送り表示
- 演出・サウンドは未定

## 8. オンライン

- 参加コードを共有して離れた2人が1対1で対戦する（ランダムマッチはしない）
- 接続は共通基盤（`OnlineSession` / `ModeSelectPanel`）を使う
- ホストだけがバトルとドラフトの抽選を計算し、ゲストは選んだ行動を送って結果を表示する
- 相手が切断したら（ドラフト中・選出中も含む）「相手が切断しました」を表示して勝ち扱い

## 9. セーブ

- 勝ち抜き戦の最高連勝数、設定（音量・メッセージの速さ）
- 勝ち抜き戦の途中経過を保存するかは未定

## 10. フォルダ・クラス構成

### 10.1 設計の考え方

- 共通基盤（`Assets/_Project/Common/`、`PenguinMonster.Common.*`）とゲーム本体（`Assets/_Project/Games/100_PenguinMonster/`、`PenguinMonster.*`）を分ける
- ルール・計算は Unity に依存しない純C#に置き、EditMode テストで確かめる
- シーン・データはコードから生成する
- バトルは「場の数」を持たせておき、ダブルスを後から足せるようにする（シングルのうちは場は1）

### 10.2 フォルダ

`Assets/_Project/Games/100_PenguinMonster/` の中身。

```text
Scripts/
├── Battle/                 # バトルのルール・計算（純C#、PenguinMonster.Battle.asmdef、noEngineReferences）
│   ├── Data/               # タイプ・相性表・能力値・技／ペンモンの定義と定義表（MoveTable / MonsterTable）
│   ├── BattleBalance.cs    # 調整値（Lv・ダメージ式の定数・選出数など）
│   ├── BattleState / BattleSide / BattleMonster   # バトルの状態（場は配列で持ち、シングルは1）
│   ├── BattleEngine(.Order).cs                    # ターンの解決（行動順 → 命中 → ダメージ → ひんし → 勝敗）
│   ├── DamageCalculator.cs
│   ├── BattleEvent.cs / BattleMessages.cs         # 起きたことの列と、その文面
│   └── CpuPlayer.cs        # CPU（よわい）
└── View/                   # 表示（MonoBehaviour、名前空間 PenguinMonster.View）
    ├── BattleController(.Playback).cs  # 進行役。入力待ちと BattleEvent の再生
    ├── MonsterPanel / MessageWindow / CommandPanel / PartyPanel
    └── TypeColors.cs       # 仮の絵の色
Editor/
└── PenguinMonsterSceneBuilder(.Panels/.Helpers).cs  # Tools > PenguinMonster > Rebuild でシーン生成
Scenes/
└── PenguinMonsterScene.unity   # 生成物（手で編集しない）
Tests/Editor/               # EditMode テスト（PenguinMonster.Battle.Tests.asmdef）
```
